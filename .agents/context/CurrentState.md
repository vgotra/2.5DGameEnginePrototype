# Current State

## Status

The engine is a Windows-first .NET 10 prototype for 2D/2.5D isometric games. The MVP vertical slice is complete: SDK/build policy, core entity and clock types, isometric math, ECS storage, backend-neutral contracts (rendering/audio/physics/platform), a deterministic tile map, continuous movement with collision and jump, camera following, Win32 window/input, and the Vulkan render path.

Rendering is split between a backend-neutral `IRenderer` contract (`BeginFrame`/`Submit(SpritePacket)`/`EndFrame`) and a single Vulkan backend that draws white diamonds with black borders in iso and white boxes in `--2d`:

- **Vulkan (`Engine.Rendering.Vulkan`)** — swapchain, render pass, per-swapchain framebuffers, SPIR-V shape shaders (GLSL compiled with glslc, copied to `shaders/` in output), graphics pipeline, descriptor pool allocator, texture uploader, and a batch renderer that accumulates submitted packets and issues one indexed draw per frame. Debug builds enable the Vulkan validation layers (`VK_LAYER_KHRONOS_validation`) with a `[UnmanagedCallersOnly]` message callback (`Debug.WriteLine`); the `VK_DEBUG_UTILS_EXTENSION_NAME` extension is enabled only in Debug so Release keeps a 2-extension instance. Frame pacing is implemented: the swapchain prefers `VK_PRESENT_MODE_MAILBOX_KHR` (fallback FIFO) with triple buffering; a 3-slot frame-in-flight pool plus per-swapchain-image fences lets the CPU overlap frames. `BeginFrame` waits/resets the slot fence BEFORE `vkAcquireNextImageKHR` (an unpaced CPU must never re-signal a pending acquire semaphore) and skips the per-image fence wait when the image's last use was the current slot (that fence is only re-signaled by the current frame's submit), with the `ErrorOutOfDateKHR` resize path re-fetching the recreated sync handles; staging→device copies are recorded into the main command buffer behind a `TRANSFER → VERTEX_INPUT` barrier with an FNV dirty gate (no per-frame `vkQueueWaitIdle`); `ErrorOutOfDateKHR` at acquire rebuilds the swapchain. `SpritePacket.Texture`/`Material` handles exist but are not yet sampled. Screen space is y-down and the vertex shader stores `gl_Position` with `ndc.y` unchanged (Vulkan NDC y = -1 maps to the top); no Y negation is applied.

Windowing (`Engine.Platform.Win32`): the window opens centered on the primary screen at 800x600. `Win32Window` reports client size through `WM_SIZE` (single source for windowed drag-resize, `F11` toggling, and `--fullscreen` start) and `SetFullscreen(bool)` switches to borderless `WS_POPUP` sized to the monitor bounds, restoring the saved rect on exit. The sample polls the size each frame and calls `camera.Resize` plus `VulkanRenderer.Resize`, which recreates the swapchain, image views, framebuffers, and per-image command resources (command pool, command buffers, semaphores, and frame-in-flight fences are recreated together on resize). The Win32 P/Invoke surface is now source-generated: `src/Engine.Platform.Win32/NativeMethods.cs` (`internal static partial class NativeMethods`) holds the 20 `[LibraryImport]` declarations and `src/Engine.Platform.Win32/Win32Types.cs` holds the blittable `POINT`/`RECT`/`MONITORINFO`/`MSG` structs; `Win32Window.cs`/`Win32Input.cs` call `NativeMethods.*`. UTF-16 string APIs use `StringMarshalling.Utf16` with explicit `W` entry points; `PeekMessage`/`DispatchMessage`/`CallWindowProc` are pinned to their `A` variants (no literal export in `user32.dll`); `TranslateMessage` is bare (literal-only); `GetWindowLongPtrW` returns `nint`. The `[UnmanagedFunctionPointer(Winapi)] WndProcDelegate` + `Marshal.GetFunctionPointerForDelegate` callback is preserved. AOT/trim-safe, runtime marshalling stubs removed (roadmap item 14).

Vulkan is the only renderer. `--2d` is a projection/geometry modifier, not a backend: the camera switches to a cartesian mapping (64px per axis) and emits axis-aligned boxes via `ShapeKind.Box` (the player is a 40x40 box in 2D, a 40x20 diamond in iso). `IsometricCamera.Follow` clamps the camera to the map bounds in screen space (iso constrains the `(x+y)`/`(x-y)` axes so the 1280x640 map stays in the viewport; cartesian constrains `x`/`y`), so when the map fits a viewport axis that axis is centered on screen and otherwise the camera follows the player.

The platform layer is cross-platform-ready (Windows only today): `Engine.Platform` defines `IGameWindow` (size, close, fullscreen, native surface), `IInputState` (polled per frame), `PlatformKind`, and `NativeWindowSurface`; `Engine.Platform.Desktop.GamePlatform.CreateWindow` is the factory that returns a `PlatformSession` and selects the Win32 backend now (throwing `PlatformNotSupportedException` elsewhere). `VulkanRenderer` consumes `NativeWindowSurface` and selects the Vulkan loader name per OS; Win32 surface is wired, X11/Wayland/macOS slots throw until the SDL2 backend lands. The sample talks only to contracts + `Engine.Platform.Desktop`. See `docs/LinuxSupportPlan.md`.

## Verification

`dotnet build Engine.sln --nologo` passes with 0 warnings and 0 errors in Debug and Release (Release solution mappings exist for all 13 projects). `dotnet run --project tests/Engine.Tests` prints `Smoke tests passed` (assertions cover iso and flat camera centering in an 800x600 viewport plus a 1920x1080 "fullscreen" viewport, flat-mode extraction count, box shape, cartesian camera mapping, and ECS entity recycle/purge). Launch probes confirmed default (no flags), `--2d`, `--fullscreen`, and `--cap 60|80|100` combos all run with the 800x600 centered window: `TotalProcessorTime` keeps growing (no hung-but-alive stalls) and `CloseMainWindow` leads to a clean exit within a timeout; mid-run window resizes (swapchain rebuild) leave the loop healthy and steady-capped. Uncapped the loop measures ~5-6% of a core (MAILBOX self-throttles to display refresh). Capped builds add a single non-main thread busy-waiting at `TimeCritical` priority (~60-95% of a core at `--cap 60`/`--cap 30`) that is independent of the main loop (whose `--cap 30` sleep measures correctly) — see `docs/FramePacingPlan.md` and `KnownIssues.md`.

## Risks

The sample loop is unpaced by default (MAILBOX present is non-blocking), so the CPU renders as fast as it can and presents each completed frame; `--cap <fps>` restores a steady cadence. The 60 Hz fixed-step sim renders multiple times per present when unpaced, which is expected. Sim-to-present interpolation is a deferred optional follow-up for refresh-rate-independent smoothness. `SpritePacket` texture/material handles are currently ignored. `vkQueueWaitIdle` remains on resize, dispose, and rare buffer growth.
