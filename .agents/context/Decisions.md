# Decisions

- Windows-first prototype with portability boundaries.
- Vortice.Vulkan is the rendering backend.
- ECS uses per-component sparse-set storage (`SparseSet<T>`), with stores registered manually via `World.Storage<T>()`; no archetype queries/scheduling yet.
- Mature external libraries are adapters, not public engine contracts.
- Shaders are compiled from GLSL source with glslc into SPIR-V and shipped under `assets/shaders/`; the Vulkan project copies them to `shaders/` in the output directory.
- `IRenderer` is the backend-neutral draw contract (`SpritePacket` submission); Vulkan maps sprites to batched shape geometry until the texture path lands.
- Vulkan NDC Y convention: screen coordinates are y-down (y = 0 at top), and the vertex shader stores `gl_Position` with `ndc.y` unchanged because Vulkan NDC y = -1 maps to the top of the framebuffer. Do not negate Y.
- Tile borders use overdraw rather than separate line geometry: the batch draws a slightly larger black diamond behind each white tile. The same technique (with `ShapeKind.Box`) produces the flat 64x64 grid in `--2d` mode.
- Fullscreen is borderless (window style `WS_POPUP` sized to the monitor bounds) rather than exclusive-mode; the Vulkan swapchain is rebuilt on size change. `F11` toggles it; `--fullscreen` starts in it.
- `--2d` is a projection/geometry modifier, not a backend: it reuses the same `IRenderer` submission by switching the camera to a cartesian mapping and emitting `ShapeKind.Box` geometry. Tile cell size stays `TileWidth` per axis (64x64 squares) so the flat grid matches the iso world scale.
- The camera clamps to the map bounds in screen space (`IsometricCamera.Follow`): when the map fits a viewport axis (typical in fullscreen) that axis is centered on screen, otherwise the camera follows the player within the map.
- Cross-platform seams: `IGameWindow` and `IInputState` are the platform contracts; `NativeWindowSurface` (`PlatformKind` + native handles) is the platform-neutral surface descriptor backends consume. `Engine.Platform.Desktop.GamePlatform.CreateWindow` is the runtime factory that registers backends; the sample never references a concrete platform. New OS-specific code goes behind a `Engine.Platform.*` backend, never into contracts or shared gameplay code.
- Linux (and later macOS) support is planned, not current: target windowing backend is SDL2 (one path for X11, Wayland, macOS; MIT licensed). The Vulkan backend selects the loader name and instance surface extension per `PlatformKind`; non-Win32 surface kinds throw `PlatformNotSupportedException` until the SDL2 backend lands (see `docs/LinuxSupportPlan.md`).
- Vulkan is the only renderer on every platform; there is no CPU fallback.
- Frame pacing: MAILBOX present (fallback FIFO) with triple buffering; a 3-slot frame-in-flight pool plus per-swapchain-image fences; staging→device copies are recorded into the main command buffer behind a `TRANSFER → VERTEX_INPUT` barrier with a per-slot byte-snapshot dirty gate (no per-frame `vkQueueWaitIdle`); `ErrorOutOfDateKHR` at acquire rebuilds the swapchain. The sample paces with `Engine.Core.FrameTimer` (`--cap`), which sleeps the floor of the remaining ms and spin-waits only the sub-ms residual. Sim-to-present interpolation is deferred.
- The batch renderer's dirty gate compares per-slot retained byte snapshots via `SequenceEqual` (on the preallocated struct buffers, pinned with `fixed` when passed to Vulkan) instead of an FNV hash scan; the hash only short-circuits when the vertex/index counts are unchanged, otherwise the snapshot arrays grow on demand.
- `IGameWindow.IsMinimized` lets the sample skip render/present while the window is minimized (the loop still pumps messages and paces); a minimized window never hits the Vulkan present path.
- The window process is set per-monitor-DPI-aware (V2) at startup (`SetProcessDpiAwarenessContext`), so the Vulkan swapchain matches physical pixels on mixed-DPI setups; the call is best-effort and failure is ignored.
- Debug-only Vulkan validation layers: `Engine.Rendering.Vulkan` enables `VK_LAYER_KHRONOS_validation` with a `[UnmanagedCallersOnly]` message callback (`ValidationCallback` → `Debug.WriteLine`) and the `VK_DEBUG_UTILS_EXTENSION_NAME` instance extension **only in Debug**; Release keeps a 2-extension instance (surface + swapchain) and never loads layers. Availability is probed once by scanning `vkEnumerateInstanceLayerProperties`, so a machine without the SDK's validation layer still runs in Debug.
- Pinned UTF-8 names instead of allocations: the Vulkan pipeline pins `"main\0"u8` for the shader entry point and the renderer pins the app/engine/extension name strings via `fixed` — no `Marshal.StringToCoTaskMemAnsi`/`StringToHGlobalAnsi` transient allocations at init (per-frame hot paths stay allocation-free).
- ECS recycle/purge semantics: `World.Destroy` bumps the entity generation and pushes the index to a free list; all component stores purge rows through the shared `ISparseSet.Remove(entity)` swap-with-last. Re-`Add` after destroy refreshes the stored entity in the sparse set, so recycled entities never read stale component data.
- JobSystem: workers use a `ConcurrentQueue` + `SemaphoreSlim` signal; `DrainAsync` tracks pending work with `Interlocked` and blocks on a completion `SemaphoreSlim` (no busy-wait). The `System.Threading.Channels` rewrite is deferred to the ECS/jobs milestone.
- Threading: `FrameTimer` stays on `Thread.Sleep` + `Thread.Yield` (deliberate for a synchronous hot loop — `Task.Delay`/`TimeProvider` timers are the wrong tool); there is no `lock`/`Monitor` to migrate to `System.Threading.Lock`. Do NOT reference `SemaphoreSlim.WaitAsync(TimeProvider)` or `ThreadPool.GetQueueCapacity/SetQueueCapacity` — absent in .NET 10 final (the runtime exposes `ThreadPool.PendingWorkItemCount` instead).
- Win32 P/Invoke is source-generated `[LibraryImport]` (`NativeMethods.cs`/`Win32Types.cs`): UTF-16 string APIs need explicit `W` entry points + `StringMarshalling.Utf16`; `PeekMessage`/`DispatchMessage`/`CallWindowProc` have no literal export in `user32.dll` and are pinned to their `A` variants (`TranslateMessage` is the lone literal-only exception); `GetWindowLongPtrW` returns `nint`. The `[UnmanagedFunctionPointer(Winapi)] WndProcDelegate` callback is preserved; a future `[UnmanagedCallersOnly]` refactor is a separate task.
