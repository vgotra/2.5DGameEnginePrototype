# Decisions

- Windows-first prototype with portability boundaries.
- Vortice.Vulkan is the rendering backend.
- ECS uses manual registration and archetype chunks.
- Mature external libraries are adapters, not public engine contracts.
- Shaders are compiled from GLSL source with glslc into SPIR-V and shipped under `assets/shaders/`; the Vulkan project copies them to `shaders/` in the output directory.
- `IRenderer` is the backend-neutral draw contract (`SpritePacket` submission); Vulkan maps sprites to batched shape geometry until the texture path lands.
- Vulkan NDC Y convention: screen coordinates are y-down (y = 0 at top), and the vertex shader stores `gl_Position` with `ndc.y` unchanged because Vulkan NDC y = -1 maps to the top of the framebuffer. Do not negate Y.
- Tile borders use overdraw rather than separate line geometry: the batch draws a slightly larger black diamond behind each white tile. The same technique (with `ShapeKind.Box`) produces the flat 64x64 grid in `--2d` mode.
- GDI reference/fallback renderer removed: Vulkan is the only renderer, so the sample has a single game loop and only `--2d`/`--fullscreen` flags.
- Fullscreen is borderless (window style `WS_POPUP` sized to the monitor bounds) rather than exclusive-mode; the Vulkan swapchain is rebuilt on size change. `F11` toggles it; `--fullscreen` starts in it.
- `--2d` is a projection/geometry modifier, not a backend: it reuses the same `IRenderer` submission by switching the camera to a cartesian mapping and emitting `ShapeKind.Box` geometry. Tile cell size stays `TileWidth` per axis (64x64 squares) so the flat grid matches the iso world scale.
- The dirty-gated `WM_PAINT` repaint machinery (`ConsumeRepaint`) and the `WM_ERASEBKGND` suppression were removed together with the GDI renderer; the STATIC-class window has no background brush, so no erase suppression is needed.
- The window opens centered on the primary screen at 800x600 (`Win32Window` centers via `GetSystemMetrics`).
- The camera clamps to the map bounds in screen space (`IsometricCamera.Follow`): when the map fits a viewport axis (typical in fullscreen) that axis is centered on screen, otherwise the camera follows the player within the map.
- Cross-platform seams: `IGameWindow` and `IInputState` are the platform contracts; `NativeWindowSurface` (`PlatformKind` + native handles) is the platform-neutral surface descriptor backends consume. `Engine.Platform.Desktop.GamePlatform.CreateWindow` is the runtime factory that registers backends; the sample never references a concrete platform. New OS-specific code goes behind a `Engine.Platform.*` backend, never into contracts or shared gameplay code.
- Linux (and later macOS) support is planned, not current: target windowing backend is SDL2 (one path for X11, Wayland, macOS; MIT licensed). The Vulkan backend selects the loader name and instance surface extension per `PlatformKind`; non-Win32 surface kinds throw `PlatformNotSupportedException` until the SDL2 backend lands (see `docs/LinuxSupportPlan.md`).
- Vulkan is the only renderer on every platform; there is no CPU fallback.
- Frame pacing (roadmap item 1, implemented): the swapchain prefers `VK_PRESENT_MODE_MAILBOX_KHR` (fallback FIFO) with triple buffering; the renderer uses a 3-slot frame-in-flight pool (`_imageAvailable`/`_renderFinished`/`_fences`) plus a per-swapchain-image fence map (`_imagesInFlight`), replacing the single in-flight fence and the per-frame `vkQueueWaitIdle`; staging→device copies are recorded into the main command buffer behind a `TRANSFER → VERTEX_INPUT` barrier with an FNV dirty gate; the sample uses `Engine.Core.FrameTimer` (Stopwatch dt, optional `--cap` frame cap); `ErrorOutOfDateKHR` at acquire rebuilds the swapchain, and ESC/window close tears down cleanly. Sim-to-present interpolation is deferred.
- `[LibraryImport]` migration (roadmap item 14, implemented): the Win32 P/Invoke surface in `Engine.Platform.Win32` is now source-generated (`src/Engine.Platform.Win32/NativeMethods.cs`, `internal static partial class NativeMethods`; the blittable `POINT`/`RECT`/`MONITORINFO`/`MSG` structs live in `src/Engine.Platform.Win32/Win32Types.cs`). `Win32Window.cs` and `Win32Input.cs` call `NativeMethods.*` and no longer declare their own `[DllImport]`s. UTF-16 string APIs (`CreateWindowExW`/`SetWindowTextW`/`GetMonitorInfoW`/`GetModuleHandleW`) carry `StringMarshalling.Utf16` and explicit `W` entry points — `[LibraryImport]` defaults to UTF-8 and uses the method/EntryPoint verbatim with no A/W suffix fallback, so both must be explicit or the binding silently changes. The message-pump trio `PeekMessage`/`DispatchMessage`/`CallWindowProc` have only `A`/`W` exports in `user32.dll` (no literal — `WinUser.h` expands them via `#ifdef UNICODE`); the old `[DllImport]` Ansi-default silently appended `A`, so we pin `PeekMessageA`/`DispatchMessageA`/`CallWindowProcA` to preserve behavior. `TranslateMessage` is the lone literal-only exception. `GetWindowLongPtrW` returns `nint` (matching native `LONG_PTR` and the setter; the old `long` return was a leftover inconsistency). `SetLastError`/`Marshal.GetLastPInvokeError()` are unused and not added. The `[UnmanagedFunctionPointer(Winapi)] WndProcDelegate` + `Marshal.GetFunctionPointerForDelegate` callback is preserved as-is; a future `[UnmanagedCallersOnly]` refactor is a separate task.
